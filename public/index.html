DB_Middle API

API Guide และหน้าทดสอบ

หน้านี้สรุปว่า API ปัจจุบันมีอะไรบ้าง, ใช้อย่างไร, ต้องส่งข้อมูลแบบไหน, และควรทดสอบลำดับไหน ถ้าต้องการลองยิง request ทันทีให้เปิดหน้า tester หรือ import เข้า Postman.

Open Web Tester Download Collection Download Environment Download Server Environment
Base URL: localhost หรือ IP ของ server ที่พอร์ต 5050 Database: DB_Middle Resource หลัก: dbo.ms_users

เรียกหน้าเว็บอย่างไร

1. Start server

npm start

2. เปิดหน้าเอกสารหรือหน้าทดสอบ

http://localhost:5050/tools/
http://192.168.19.249:5050/tools/

3. เลือก URL ให้ตรงกับที่เปิด

Web Tester ใช้ host เดียวกับหน้าที่เปิดโดยอัตโนมัติ ส่วน Postman ให้เลือก Local หรือ Server Environment

แนะนำลำดับการทดสอบ

Health Check

เริ่มจาก `GET /health` เพื่อเช็กว่า API คุยกับ SQL Server ได้ก่อน

Read

ใช้ `POST /api/users` และ `POST /api/users/:userID` เพื่อดูว่าข้อมูลอ่านออกปกติ

Write

ค่อยทดสอบ `POST`, `PUT`, `DELETE` กับ userID ตัวอย่างที่ไม่ชนข้อมูลจริง

รายการ API ปัจจุบัน

GET /

ใช้ดูว่า API server ทำงานอยู่ และแสดงชื่อฐานข้อมูลที่ตั้งค่าไว้

{
  "message": "SQL Server API is running",
  "database": "DB_Middle"
}
GET /health

ใช้เช็กสถานะการเชื่อมต่อ SQL Server

{ "status": "ok" }
GET /api/db-test

ใช้ยืนยันว่า query กับฐานข้อมูลได้จริง พร้อมเวลาจาก server

{
  "success": true,
  "data": {
    "database_name": "DB_Middle",
    "server_time": "2026-04-09T..."
  }
}
POST /api/users

ค้นหาข้อมูลผู้ใช้จาก `dbo.ms_users` โดยส่ง `username`, `password`, `userbarcode` ใน body หรือในไฟล์ JSON

{
    "username": "1",
    "password": "1",
    "userbarcode": "1"
}
POST /api/users/:userID

ดึงข้อมูลผู้ใช้รายคนตาม `userID`

ตัวอย่าง: POST /api/users/1
POST /api/users/create

เพิ่มผู้ใช้ใหม่ ต้องส่ง JSON body ที่มี `userID` และ field อื่นตามต้องการ

{
  "userID": "U001",
  "fullname": "John Doe",
  "positioncode": "DEV",
  "userbarcode": "123456789",
  "username": "jdoe",
  "password": "secret",
  "photo": null,
  "adminid": "A001",
  "pathphoto": null,
  "wardcode": "W01",
  "roomcode": "R01",
  "firstname": "John",
  "lastname": "Doe",
  "departmentcode": "IT"
}
POST /api/prescriptions

ค้นหา prescription จาก `dbo.prescription` โดยส่ง `prescriptionno`, `hn`, `an`, `orderitembarcode` ใน body หรือในไฟล์ JSON

{
  "prescriptionno": "RX0001",
  "hn": "123456",
  "an": "654321",
  "orderitembarcode": "ITEM001"
}
POST /api/prescriptions/ward-summary

สรุปจำนวน order แยกตาม ward และวันที่สั่งยา โดยรับค่า where ผ่าน `startDate`, `endDate`, `wardcode`, `wardname` และ `genorderdatetimeIsNull`

{
  "startDate": "2024-10-30 00:00:00",
  "endDate": "2024-10-30 23:59:59",
  "wardcode": "03",
  "genorderdatetimeIsNull": true
}
POST /api/prescriptions/:prescriptionno

ดึง prescription ตามเลขใบยา โดยตอบกลับเป็นรายการทั้งหมดของ prescription นั้น

ตัวอย่าง: POST /api/prescriptions/RX0001
PUT /api/users/:userID

แก้ไขข้อมูลผู้ใช้ตาม `userID` ใน path โดยส่งค่าที่ต้องการอัปเดตใน body

ตัวอย่าง: PUT /api/users/U001
DELETE /api/users/:userID

ลบผู้ใช้ตาม `userID`

ตัวอย่าง: DELETE /api/users/U001

ใช้กับ Postman อย่างไร

1. Import Collection

นำเข้าไฟล์ `Interface_api.postman_collection.json`

2. Import Environment

นำเข้าไฟล์ `Interface_api.local.postman_environment.json` เพื่อแยกตัวแปร `baseUrl` และ `userID`

3. เลือก Environment

เลือก environment ที่มุมขวาบนของ Postman แล้วค่อยกด request ที่ต้องการ

หมายเหตุการทดสอบ

ถ้า `POST` ล้มเหลว อาจเกิดจาก `userID` ซ้ำในฐานข้อมูล

ถ้า `PUT` หรือ `DELETE` ได้ 404 แปลว่าไม่พบ `userID` ที่ส่งเข้าไป

ถ้ารัน server บนพอร์ตอื่น ให้แก้ `baseUrl` ในหน้า tester หรือ Postman environment ให้ตรงกัน
